## 가장 중요한 운영 원칙 3개

1. **한의원 기본 정보는 한 곳에서 관리**: `_data/clinic.yml`
2. **FAQ는 한 곳에서 관리**: `_data/faq.yml`
3. **건강 칼럼은 `_posts`에 글 파일 하나씩 추가**

이렇게 하면 같은 정보를 여러 페이지에서 따로 고치다가 서로 달라지는 일을 줄일 수 있습니다.

## 1. FAQ 문구를 고치는 가장 쉬운 방법

GitHub 저장소에서:

`_data` → `faq.yml` → 연필 아이콘(Edit)

각 질문은 아래처럼 되어 있습니다.

```yml
- question: "토요일에도 진료하나요?"
  answer: >-
    현재 안내 기준 토요일은 오전 9시부터 오후 2시까지 진료합니다.
```

`question:` 또는 `answer:` 뒤의 문장만 수정하고 **Commit changes**를 누르면 됩니다.

FAQ 화면과 FAQ 구조화데이터가 **같은 파일을 사용하므로 한 번만 수정하면 둘 다 같이 바뀝니다.**

## 2. 칼럼을 추가하는 가장 쉬운 방법

GitHub 저장소에서:

`_posts` → **Add file** → **Create new file**

파일 이름은 반드시 날짜로 시작합니다.

```text
2026-09-01-neck-stiffness-morning.md
```

내용은 `_drafts/article-template.md`를 복사해서 사용하세요.

최소 형식:

```md
---
title: "아침에 일어났을 때 목이 뻣뻣한 이유"
description: "아침에 목이 뻣뻣할 때 확인할 생활습관과 빠른 평가가 필요한 신호를 정리합니다."
category: "통증"
keywords:
  - "목 뻣뻣함"
  - "목 통증"
  - "수원 한의원"
author: "약손한의원 의료진"
---

## 먼저 답하면

첫 문단에서 질문에 바로 답합니다.

## 어떤 경우에 이런 불편이 생길 수 있나요?

본문...

## 이런 증상이 있으면 우선 다른 의료기관 평가가 필요합니다

본문...

## 진료할 때 알려주면 좋은 내용

본문...
```

Commit하면 자동으로:

- 독립 건강정보 페이지 생성
- `/articles/` 목록에 표시
- `sitemap.xml`에 포함
- `feed.xml`에 포함
- `llms.txt` 건강정보 목록에 포함
- Article 구조화데이터 생성
- 같은 카테고리의 관련 글 자동 연결

이 됩니다.

## 3. 글을 수정했을 때

본문을 크게 수정했다면 front matter에 아래 한 줄을 추가하거나 날짜를 바꿉니다.

```yml
updated: 2026-09-15
```

그러면 화면에 최종 수정일이 표시되고 Article 구조화데이터의 `dateModified`에도 반영됩니다.

특정 의료진 개인 명의로 작성하거나 검토한 글이라면 사실에 맞는 경우에만 아래를 사용합니다.

```yml
author: "OOO 한의사"
author_type: "Person"
reviewed_by: "OOO 한의사"
```

원장/한의사 이름을 아직 사이트에 공개하지 않을 경우 기본값인 `약손한의원 의료진`을 그대로 사용하면 됩니다.

## 4. 참고자료가 필요한 글

의학적 수치, 공공기관 권고, 진료지침 등 외부 근거를 사용한 경우 글 상단에 다음을 추가할 수 있습니다.

```yml
sources:
  - title: "공공기관 또는 학회 자료명"
    url: "https://example.org/source"
```

그러면 글 아래에 `참고자료` 영역이 자동 생성됩니다.

## 5. AI 검색을 위해 들어간 구조

- 로그인 없이 읽을 수 있는 정적 HTML
- `robots.txt`에서 `OAI-SearchBot` 접근 허용
- `sitemap.xml` 자동 생성
- RSS `feed.xml`
- `MedicalClinic + LocalBusiness` 구조화데이터
- 건강글 `Article` 구조화데이터
- FAQ의 화면 내용과 같은 원본을 사용하는 `FAQPage` 데이터
- `/clinic-facts/` 한의원 핵심 사실 페이지
- `/editorial-policy/` 건강정보 작성·검토 원칙
- `/llms.txt` 사이트 주요 페이지와 전체 건강정보 문서 색인
- 작성일·수정일·작성 주체 표시
- 같은 주제 글끼리 내부 링크 자동 생성

`llms.txt` 자체는 AI 검색 노출을 보장하는 공식 표준이 아닙니다. 실제 핵심은 **공개 크롤링 가능성 + 명확한 사실 + 독립 URL을 가진 좋은 콘텐츠 + 사이트맵 + 외부에서 확인 가능한 일관된 기관 정보**입니다.

OpenAI의 검색 노출 관점에서는 `OAI-SearchBot`이 차단되지 않는 것이 중요합니다. `GPTBot`은 검색 노출과 별개로 모델 학습 관련 크롤러이므로, 향후 학습 허용 여부를 별도로 정하고 싶다면 `robots.txt`에서 따로 설정할 수 있습니다.

## 6. 어떤 칼럼부터 쌓을까?

처음에는 **환자가 실제로 검색할 질문 1개 = 글 1개** 방식이 좋습니다.

추천 순서:

1. 아침에 목이 뻣뻣한 이유
2. 목 통증과 팔 저림이 같이 있을 때 확인할 점
3. 허리가 갑자기 아플 때 병원 평가가 먼저 필요한 경우
4. 무릎이 계단에서 아픈 이유는 하나일까?
5. 약침 치료 전 복용약을 알려야 하는 이유
6. 두통과 어지럼이 같이 있을 때 위험 신호
7. 명치가 답답하고 더부룩할 때 기록하면 좋은 것
8. 스트레스를 받으면 배가 아픈 이유
9. 잠들기 어렵고 자주 깨는 경우 확인할 생활요인
10. 갱년기 상열감과 수면 불편이 같이 있을 때

**주 1~2개** 정도면 충분합니다. 30개, 50개가 되어 갈수록 개별 질문에 답하는 자료망이 생깁니다.

## 8. 실제 진료정보를 고치는 곳

주소, 전화번호, 진료시간 등은 `_data/clinic.yml`에서 수정합니다.

특히 다음 항목은 원내 실제 운영과 반드시 일치해야 합니다.

- 평일/토요일 진료시간
- 점심시간
- 일요일/공휴일 휴진 여부
- 주소 및 층수
- 전화번호
- 외부 공식 채널

의료진 약력, 비용, 시술·치료 범위, 치료 효과 등의 내용은 확인된 사실만 게시하세요.
